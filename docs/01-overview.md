# 概要とルール

## 概要とスコープ

RealWorld（Conduit）相当のブログ投稿サービスを、Void の上で作る。目的は、ドメインが複数あってドメインをまたぐ処理が出る規模で、Void のどこに何を置けば読めるコードになるかを確かめること。実運用はしない。

- 対象：会員（プロフィール）、記事（タグを含む）、反応（いいね・コメント）、フォロー
- 入れるもの：登録・ログイン、プロフィールの表示と編集、記事の作成・編集・削除（本文は Markdown）、タグ、記事一覧（全体の新着・フォロー中の新着・タグ絞り込み・会員の記事・会員がいいねした記事、ページ送り）、いいね、コメントの投稿と削除、フォロー、よく使われているタグ
- 入れないもの：メール確認、パスワード再設定、画像アップロード（アイコンは URL を入れるだけ）、下書き、コメントの編集と返信、通知、全文検索、管理者、退会、同時更新の対策

RealWorld に合わせるのは機能の範囲だけ。RealWorld が決めている API の形（JSON の形、JWT 認証）には合わせず、Void の pages（loader と action）と Void の認証で作る。

詳細はほかの3本に分けている（`02-domain.md`、`03-database.md`、`04-pages.md`）。

## 技術スタック

`pnpm create void` の雛形（React + D1 + Vite+）のまま。

| 用途 | 採用するもの |
|---|---|
| フレームワーク | Void（pages モード、React） |
| 実行環境 | Cloudflare Workers |
| DB | D1（Drizzle。`void/db` と `void/schema-d1`） |
| 認証 | Void の認証（中身は Better Auth。メールとパスワード） |
| バリデーション | zod（`void/drizzle-zod` と `defineHandler.withValidator`） |
| Markdown | 未定（表示のときに HTML にして、サニタイズする） |
| UI | 入れない。CSS もほぼ書かない。見たいのは画面ではなくコードなので |

## ルール

ルールはこの表で全部。表にないことはやらない。

| ルール | 決定内容 |
|---|---|
| 閲覧 | 記事・記事一覧・プロフィールは誰でも読める。書き込みはすべてログインが要る |
| ユーザー名 | 登録時に決める。英小文字・数字・`_` の3〜20文字で、全会員で重複しない。あとから変えられない（プロフィールの URL に使うので） |
| 記事の編集・削除 | 書いた本人だけ |
| 記事の URL | `slug` で引く。作成時にタイトルから作り、重複しないよう末尾にランダムな6文字を付ける。タイトルを直しても `slug` は変えない |
| タグ | 1記事に5個まで。前後の空白を落として小文字にし、同じタグは1つにまとめる。記事の編集で付け替えられる |
| 記事の削除 | 付いていたいいね・コメント・タグ付けも一緒に消える。タグそのものは残る |
| いいね | 1人1記事に1回。自分の記事にもできる。もう一度押すと取り消し |
| コメント | 投稿と削除だけ。消せるのは書いた本人だけ |
| フォロー | 自分自身はフォローできない。もう一度押すと解除 |
| 記事一覧 | 新しい順に1ページ10件 |
| よく使われているタグ | 付いている記事の数が多い順に上位20件 |
| 日時 | 保存は UTC。表示は日付だけでよい |

- [ ] 記事を書いて一覧と詳細に出す
- [ ] いいね・コメント・フォローを足す
- [ ] フォロー中の新着、タグ、ページ送り、プロフィール編集
