# ドメイン

## ドメインモデル

会員（Profile）、記事（Article）、タグ（Tag）、いいね（Favorite）、コメント（Comment）、フォロー（Follow）。

| モデル | 持つもの |
|---|---|
| Profile | 会員の ID（認証のユーザー ID と同じ）、表示名、自己紹介、アイコン画像の URL |
| Article | slug、タイトル、概要、本文（Markdown）、書き手、タグ、作成日時、更新日時 |
| Tag | 名前 |
| Favorite | 会員、記事 |
| Comment | 記事、書き手、本文、作成日時 |
| Follow | フォローする会員、フォローされる会員 |

**認証のユーザーとプロフィールは分ける。** 認証のユーザー（Better Auth の `user`）は Void の標準のまま使い、メールアドレス・パスワード・ユーザー名（`name`）を持つ。登録は画面から `auth.signUp.email` を呼ぶだけで、プロフィールは作らない。プロフィールは設定画面で初めて保存したときに作り、行がない会員は「表示名なし・自己紹介は空・アイコンなし」として扱う。認証のユーザーから画面に出すのはユーザー名だけにして、メールアドレスが漏れる経路を作らない。

## コードの置き場所

ドメインごとに `src/domains/<ドメイン>/` に置く。読むものは `queries.ts`、書くものは `commands.ts`。`pages/*.server.ts` は、入力を確かめて、ここの関数を呼んで、返すか移動させるだけにする。

Better Auth の `user` テーブルは Void が `.void/better-auth-schema.ts` に生成する。これを import するのは `src/domains/users/table.ts` だけにして、ほかのファイルはそこから `users` として読む。

## ドメインをまたぐ処理

このアプリで置き場所を考えたいのはここ。

| 処理 | またぐもの | 中身 |
|---|---|---|
| 記事の一覧と詳細 | 記事、会員、反応、フォロー | 記事に、書き手のプロフィール、いいね数、自分がいいね済みか、自分が書き手をフォロー済みかを付けて返す |
| フォロー中の新着 | フォロー、記事 | 自分がフォローしている会員の記事だけを並べる |
| 会員がいいねした記事 | 反応、記事 | いいねした記事を並べる |
| 記事の削除 | 記事、反応 | いいね・コメント・タグ付けを一緒に消す |
| 会員の表示 | 認証、会員 | ユーザー名は認証のユーザーから、表示名とアイコンはプロフィールから取る。プロフィールがなければ空 |

「自分がいいね済みか」「フォロー済みか」は見ている人によって変わる。訪問者には常に false を返す。

## 不変条件の置き場所

| 置き場所 | 守るもの |
|---|---|
| DB | slug・タグ名の重複なし、いいね・フォロー・タグ付けの重複なし、記事削除時の連鎖削除、外部キー |
| アプリ | ユーザー名の形と重複（Better Auth は `name` を確かめないので、`auth.ts` の `databaseHooks.user.create.before` で守る）、書き手本人だけが記事を編集・削除できる、本人だけがコメントを消せる、自分をフォローできない、タグは5個まで、タグ名の正規化 |

## 計算値

| 値 | 決め方 |
|---|---|
| いいね数 | 保存せず、いいねの件数を数える。数と実体を二重に持たない |
| 自分がいいね済みか | 見ている人のいいねがあるか。訪問者は false |
| 自分がフォロー済みか | 見ている人のフォローがあるか。訪問者は false |
| よく使われているタグ | タグ付けの件数を数える |

## まだ決めていないこと

- `void/db` を `src/domains/` の中だけに閉じ込めるか。いまは `pages/*.server.ts` から `src/domains/<ドメイン>/` の関数を呼び、`.server.ts` では `void/db` を import していない。規則にするかは、いいね・フォローが入ってから決める
